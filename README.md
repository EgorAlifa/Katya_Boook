# Скрипты сборки книги «Вместе с космонавтами»

Пайплайн в 5 шагов. Каждый следующий шаг зависит от файла, созданного предыдущим.

## Правки против оригинала
- Картинки идут в размере и с поворотом **из самого оригинального docx**
  (`wp:extent`/`a:xfrm/@rot` в `word/document.xml` — см. шаг 1.5 ниже), а не
  пересчитанном pandoc-эвристикой размере. Раньше (до этого прогона) любой
  поворот был запрещён как «баг» — это было ошибкой: пара фигур в оригинале
  специально повёрнута автором на 90/180/270°, чтобы дать
  панорамной карте/фото развернуться на всю высоту полосы; теперь пайплайн
  просто переносит `rot`/размер как есть, без своей отсебятины.
- Стиль (цвета, шрифты, отступы) сверен с эталонным прогоном `вар 3 (1).pdf`.
- На заголовках, подписях к рисункам, метках задач/ответа и врезке
  «Это интересно» включены `keepNext`/`keepLines`/`cantSplit` — раньше
  Word мог оторвать заголовок или подпись от их содержимого разрывом
  страницы («разрывы» из исходной версии).
- Линии (разделители, рамка врезки, колонтитулы, левая линия у подзаголовка)
  сделаны тоньше (`border.size` уменьшен, в среднем вдвое).

## 0. Подготовка
- Исходный docx книги конвертируется в markdown через pandoc:
  `pandoc -t markdown "вар22223333.docx" -o book.md`
- Картинки распаковываются из docx (это обычный zip):
  `unzip "вар22223333.docx" -d original_unzip`
  Сами файлы картинок лежат в `original_unzip/word/media/`, их нужно скопировать
  в папку `img/`, на которую смотрит `design.js` (переменная `IMG_DIR`).

## 1. parse_book.py
Читает `book.md`, режет его на ~630 блоков по пустым строкам, отдельно
выделяет grid-таблицы pandoc (рамки из `+---+`). Результат: `parsed_raw.json`.

## 1.5. extract_image_layout.py
Отдельно от pandoc — читает **сырой** `original_unzip/word/document.xml` (plus
`_rels`) и для каждого `<w:drawing>` достаёт настоящие `wp:extent` (размер в
EMU, в котором Word показывает картинку) и `a:xfrm/@rot` (угол поворота,
1/60000 градуса → градусы), сопоставляя `r:embed` → имя файла через
`document.xml.rels`. Нужен, потому что pandoc даёт только «сырые» пиксели
файла и никогда — угол поворота. Результат: `image_layout.json`
(`{имя_файла.jpeg: [{w_in, h_in, rotation, flipH, flipV}, ...]}` — список,
т.к. один файл иногда используется больше одного раза; сопоставляется с
блоками `classified.json` по порядку появления). Требует `original_unzip/`
из шага 0 и пакет `lxml` (`pip install lxml`).

## 2. classify_book.py
Читает `parsed_raw.json`, каждый блок размечает по типу: `chapter_mark`,
`chapter_title`, `subheading`, `task_label`, `answer_label`, `para_dropcap`,
`para`, `image`, `caption`, `callout`, `table`/`dashtable`. Тут же разбираются
все обнаруженные варианты вёрстки картинок (обычная, во врезке-цитате,
приклеенная к тексту абзаца) и врезки «Это интересно» (парсятся из
grid-таблиц в заголовок+текст+картинки). В конце каждая картинка обогащается
реальным размером/углом поворота из `image_layout.json` (шаг 1.5) — если
файла нет, откатывается на пиксели pandoc и поворот 0 с предупреждением в
консоль. Результат: `classified.json`.

## 3. design.js
Не запускается сам по себе — это модуль с «дизайн-системой»: все визуальные
константы (цвета, шрифты, отступы) и функции-строители параграфов/врезок/
подписей/колонтитулов на базе библиотеки `docx` (npm). Именно тут нужно
менять кегль, интервалы, оформление буквицы, оформление условий задач и т.д.

## 4. build-full.js
Главный генератор. Требует `npm install docx` в той же папке.
Загружает `classified.json`, режет на сегменты (введение / глава 1/2/3 /
заключение), для каждого блока вызывает нужную функцию из `design.js`,
собирает финальный `.docx` через библиотеку `docx`, попутно строит
оглавление с реальными номерами страниц (для этого нужен предварительный
рендер в PDF и `toc_pages.json` с найденными страницами — см. ниже) и
колофон. Результат: `book_full.docx`.

Запуск: `node build-full.js`

### Про оглавление (toc_pages.json)
Номера страниц в «Содержании» — не выдумка Word, а посчитаны по факту:
1. Собрать документ БЕЗ раздела «Содержание» (первый прогон).
2. Сконвертировать в PDF (LibreOffice/soffice --headless --convert-to pdf).
3. `pdftotext -layout book_full.pdf` + поиск текста заголовков по страницам
   → сохранить в `toc_pages.json`.
4. Пересобрать `build-full.js` — на этот раз он подхватит `toc_pages.json`
   и вставит реальные номера в раздел «Содержание».

## Что чаще всего нужно менять
- **Кегль/интервалы текста** → `design.js`, функция `body()` и `bodyDropCap()`,
  поля `size` (в полупунктах, 21 = 10.5pt) и `spacing.line`.
- **Размер/поворот картинок** → картинки идут в размере и повороте **из
  оригинального docx** (`im.w`/`im.h`/`im.rotation` — см. шаг 1.5,
  `extract_image_layout.py`), не из pandoc-эвристики. `figureParagraph()` /
  `figureRow()` принимают `maxWidthIn`/`maxHeightIn` только как аварийный
  потолок на случай, если фото не влезает в полосу набора — это не целевой
  размер и не должно использоваться для намеренного уменьшения/увеличения
  (для повёрнутых на 90/270° фигур `build-full.js` сам подставляет высоту
  почти во всю полосу — `PAGE_BODY_H_IN` — вместо обычного потолка, чтобы
  панорама заняла страницу целиком, как в оригинале). Байты файла пишутся
  как есть (`imageRunFromFile`), единственная применяемая трансформация —
  поворот, и только если он был в оригинале (`ImageRun`
  `transformation.rotation`); от себя пайплайн ничего не поворачивает.
- **Оформление задач/ответов** → `design.js`, функции `taskLabel()`,
  `answerLabel()`, `answerBox()`.
- **Буквица** → `design.js`, функция `bodyDropCap()`.
- **Формат страницы/поля** → `design.js`, константы `PAGE_W`, `PAGE_H`,
  `MARGIN_*` (в твипах, 1440 = 1 дюйм).
