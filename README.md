# Скрипты сборки книги «Вместе с космонавтами»

Пайплайн в 5 шагов. Каждый следующий шаг зависит от файла, созданного предыдущим.
Результат — **полностью редактируемый .docx** (не картинка-под-видом-Word): реальные
именованные стили Word, реальное автообновляемое оглавление, реальные формулы через
Word Equation, реальная автонумерация страниц/глав. Подробности — в разделе
«Редактируемость» ниже.

## 0. Подготовка
- Исходный docx книги конвертируется в markdown через pandoc:
  `pandoc -t markdown "вар22223333.docx" -o book.md`
- Картинки распаковываются из docx (это обычный zip):
  `unzip "вар22223333.docx" -d original_unzip`
  Сами файлы картинок лежат в `original_unzip/word/media/`, их нужно скопировать
  в папку `img/`, на которую смотрит `design.js` (переменная `IMG_DIR`).

## 1. parse_book.py
Читает `book.md`, режет его на ~630 блоков по пустым строкам, отдельно
выделяет grid-таблицы pandoc (рамки из `+---+`). Результат: `parsed_raw.json`.

## 1.5. extract_image_layout.py
Отдельно от pandoc — читает **сырой** `original_unzip/word/document.xml` (plus
`_rels`) и для каждого `<w:drawing>` достаёт настоящие `wp:extent` (размер в
EMU, в котором Word показывает картинку) и `a:xfrm/@rot` (угол поворота,
1/60000 градуса → градусы), сопоставляя `r:embed` → имя файла через
`document.xml.rels`. Нужен, потому что pandoc даёт только «сырые» пиксели
файла и никогда — угол поворота. Результат: `image_layout.json`
(`{имя_файла.jpeg: [{w_in, h_in, rotation, flipH, flipV}, ...]}` — список,
т.к. один файл иногда используется больше одного раза; сопоставляется с
блоками `classified.json` по порядку появления). Требует `original_unzip/`
из шага 0 и пакет `lxml` (`pip install lxml`).

## 2. classify_book.py
Читает `parsed_raw.json`, каждый блок размечает по типу: `chapter_mark`,
`chapter_title`, `subheading`, `task_label`, `answer_label`, `para_dropcap`,
`para`, `image`, `caption`, `callout`, `formula`, `table`/`dashtable`. Тут же
разбираются все обнаруженные варианты вёрстки картинок (обычная, во
врезке-цитате, приклеенная к тексту абзаца/буквице) и врезки «Это интересно»
(парсятся из grid-таблиц в заголовок+текст+картинки). `FORMULA_RE` отдельно
вылавливает формулу синодического периода (`1/S=1/T~..~ -- 1/T~..~`) из
окружающего предложения и превращает её в отдельный блок `formula`, а
`strip_md()` разворачивает pandoc-подстрочники `T~Земли~` → `T(Земли)` (в
самой формуле — как настоящий Word Equation, см. шаг 3/4). В конце каждая
картинка обогащается реальным размером/углом поворота из `image_layout.json`
(шаг 1.5). Результат: `classified.json`.

## 3. design.js
Не запускается сам по себе — модуль с «дизайн-системой». Экспортирует:
- **`WORD_STYLES`** — массив настоящих Word paragraph styles (`Title`,
  `Subtitle`, `Heading1/2/3`, `BodyText`, `FirstParagraph`, `Caption`,
  `Question`, `Task`, `Answer`, `Interesting`, `Formula`, `Header`, `Footer`).
  Каждый блок книги рендерится через `style: "<id>"`, а не разовым
  форматированием — поэтому правка стиля в Word правит все его инстансы разом.
- **`CHAPTER_NUMBERING`** — настоящая автонумерация Word (`ГЛАВА %1`),
  навешивается точечно на 3 параграфа реальных глав (не на весь `Heading1` —
  иначе «ВВЕДЕНИЕ»/«ЗАКЛЮЧЕНИЕ» тоже пронумеровались бы как главы).
- функции-строители параграфов/врезок/подписей/формул/колонтитулов поверх
  этих стилей.

Именно тут нужно менять кегль, интервалы, цвета, оформление буквицы и т.д. —
см. «Что чаще всего нужно менять» ниже.

## 4. build-full.js
Главный генератор. Требует `npm install docx` в той же папке.
Загружает `classified.json`, режет на сегменты (введение / глава 1/2/3 /
заключение), для каждого блока вызывает нужную функцию из `design.js`,
собирает финальный `.docx` через библиотеку `docx` с
`styles: {paragraphStyles: WORD_STYLES}`, `numbering: {config:
[CHAPTER_NUMBERING]}` и `features: {updateFields: true}` (последнее — чтобы
Word сам пересчитал оглавление и остальные поля при открытии файла).
Оглавление — не текст, а настоящее поле `TableOfContents` (см. ниже), строится
из блоков `Heading1`/`Heading2`. Результат: `book_full.docx`.

Запуск: `node build-full.js`

### Про оглавление
Раньше (до этого прогона) страницы для «Содержания» вычислялись отдельным
скриптом в два прохода (черновой рендер в PDF → `pdftotext` → поиск заголовков
по страницам → статический текст). Это было хрупко и не «настоящее» оглавление
Word — при редактировании текста номера страниц просто переставали быть верными.
Теперь вместо этого используется **`new TableOfContents("Содержание", {hyperlink:
true, headingStyleRange: "1-2"})`** из библиотеки `docx` — это настоящее поле
`{ TOC \h \o "1-2" }`, как если бы вы вставили оглавление через
References → Table of Contents в самом Word. Оно:
- пересчитывает номера страниц САМО при открытии файла (`updateFields: true`
  в свойствах документа просит Word обновить поля на старте — так же можно
  вручную: References → Update Table, или F9 на выделенном оглавлении);
- при добавлении/удалении глав, абзацев, страниц просто обновляется заново —
  никакого отдельного шага сборки для этого больше не нужно.

  ⚠️ Особенность проверки: у LibreOffice в headless-режиме (`soffice --convert-to
  pdf`) это поле разворачивается не полностью — рендерится пустым или лишь
  частично, если не выполнить `.uno:UpdateAll` через UNO-скрипт. Реальный
  Microsoft Word разворачивает поле нормально при открытии. Мы проверили сам
  механизм (заголовки находятся, номера страниц верные) через
  `doc.getTextFields().refresh()` + `getDocumentIndexes()` в LibreOffice UNO API —
  содержимое подтягивается корректно, просто не всегда переразбивается на
  страницы в headless-конвертации. В самом Word это не проблема.

## Редактируемость (главный приоритет)
- **Только 3 шрифта**: Merriweather (`FONT_BODY`, основной текст),
  Manrope (`FONT_HEAD`, заголовки/навигация/подписи), JetBrains Mono
  (`FONT_MONO`, формулы, номера рисунков/задач, номера страниц — «технические
  обозначения и числовые данные», а не проза).
- **Палитра — 6 фиксированных цветов**: Deep Space `#0B1D3A`, Blue `#1F3A6D`,
  Mars Orange `#E4572E` (только точечный акцент — задачи/вопросы/маркеры,
  никогда не заливка), Warm Paper `#F7F6F2` (не используется как фон
  страницы — книга печатается на белой/кремовой бумаге, а не с залитым фоном
  в файле), Dark Text `#17202A` (весь основной текст — тёмный, не синий),
  Muted Gray `#6B7280`.
- **Формулы — настоящие Word Equation** (`Math`/`MathFraction`/`MathRun` из
  `docx`), не скриншоты — открываются в редакторе формул Word, полностью
  редактируемые. Номера рисунков/задач остаются как обычный текст (это
  собственная схема нумерации оригинала — «2-11», «глава-номер», а не
  сквозной счётчик, поэтому это не заменено на авто-нумерованный список
  Word: это исказило бы смысл номеров).
- **Изображения** — реальные `ImageRun` в собственных параграфах (полноценно
  заменяемые в Word: правый клик → «Изменить рисунок»), без floating/
  Square-обтекания текстом — блочные картинки не съезжают при правке текста
  до/после них, это осознанный выбор ради стабильности при редактировании.
- **Переносы страниц/секций** — только `type: "nextPage"` в `properties`
  каждой секции, ни одного искусственного пустого абзаца-цепочки Enter'ов.
- **Номера страниц** — `PageNumber.CURRENT`, настоящее поле Word, а не
  вписанный вручную текст.

## Что чаще всего нужно менять
- **Кегль/интервалы текста** → `design.js`, стиль `BodyText`/`FirstParagraph`
  в `WORD_STYLES` (или прямо в Word: правой кнопкой на стиле «Body Text» →
  «Изменить» — разойдётся по всему документу).
- **Цвета/шрифты вообще** → `design.js`, константы `NAVY`/`BLUE`/`ORANGE`/
  `PAPER`/`INK`/`GRAY` и `FONT_BODY`/`FONT_HEAD`/`FONT_MONO` в самом верху
  файла — от них наследуются все стили в `WORD_STYLES`.
- **Размер/поворот картинок** → картинки идут в размере и повороте **из
  оригинального docx** (`im.w`/`im.h`/`im.rotation` — см. шаг 1.5,
  `extract_image_layout.py`), не из pandoc-эвристики. `figureParagraph()` /
  `figureRow()` принимают `maxWidthIn`/`maxHeightIn` только как аварийный
  потолок на случай, если фото не влезает в полосу набора — это не целевой
  размер (для повёрнутых на 90/270° фигур `build-full.js` сам подставляет
  высоту почти во всю полосу — `PAGE_BODY_H_IN` — вместо обычного потолка,
  чтобы панорама заняла страницу целиком, как в оригинале). Байты файла
  пишутся как есть, единственная применяемая трансформация — поворот, и
  только если он был в оригинале.
- **Оформление задач/ответов/вопросов** → `design.js`, стили `Task`/
  `Answer`/`Question` в `WORD_STYLES` + функции `taskLabel()`,
  `answerLabel()`, `questionHeading()`.
- **Буквица** → `design.js`, функция `bodyDropCap()`, стиль `FirstParagraph`.
- **Формат страницы/поля** → `design.js`, константы `PAGE_W`, `PAGE_H`,
  `MARGIN_*` (в твипах, 1440 = 1 дюйм). Оставлен родной формат книги
  165×235 мм (не A4) — это уже настоящий книжный тираж, а не A4-документ.

## ⚠️ Важно при правке `design.js`
Никогда не указывайте одновременно `style: "..."` и `heading: HeadingLevel...`
в одном параграфе — `heading:` сам навешивает встроенный стиль Word (`Heading1`
и т.п.), и если ещё раз передать `style:`, в XML попадут ДВА `<w:pStyle>`
подряд — это ломает распознавание заголовков для автооглавления (проверено:
оглавление после такой ошибки строится пустым). Для параграфа, которому нужен
СВОЙ стиль (не встроенный `HeadingN`) но который должен попадать в оглавление
как заголовок — задайте у стиля `outlineLevel` в `WORD_STYLES` вместо `heading:`
(см. `questionHeading()`/стиль `Question` как пример).
